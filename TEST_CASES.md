# Контрольные проверки

## Расширенная проверка и исправления 13.2

На опубликованной версии 13.1 в Chrome проверены: пустой, нулевой и отрицательный вес; превышение максимума веса; отрицательная доплата; нулевой километраж; свой маршрут с ручными расстоянием и ставкой (1000 км × 100 ₽/км = 100 000 ₽); смена типов груза; возврат из ВЭД во внутренний режим; блокировка морских базисов на авто, ЖД, авиа и мультимодальном транспорте; открытие всех 11 базисов; суммы статей и итогов в проверенных таблицах; распределение погрузки FAS; копирование внутреннего расчёта и международных условий в буфер Chrome. Это функциональная проверка, не экспертная юридическая валидация Incoterms.

Найдены и исправлены: игнорирование предельных значений основных полей; молчаливое обнуление отрицательных доплат; отображение срока при некорректных исходных параметрах. Также пустая стоимость груза теперь требует ввода вместо автоматического нуля.

Для пакета 13.2 выполнены 34 целевые проверки в Node VM: границы полей и отрицательные/пустые значения, необязательные доплаты, скрытые поля другого транспорта/режима, скрытие срока и сравнения при ошибке, сетевой отказ и неверный ответ для курса, тарифного файла и OSRM. Отказы сервисов имитировались; это не реальное отключение сети в Safari. Повторены 12 регрессий 13.1. Все 46 проверок пройдены; синтаксис app.js проверен Node --check.

После публикации 13.2 проверить: вес 5001 т — ошибка без стоимости/срока; отрицательная доплата — ошибка; возврат корректных значений — восстановление результата; CIF и ручной срок 3 суток — прежние результаты. Эти браузерные проверки нового пакета пока не выполнены. Копирование на реальном iPhone также не подтверждено.

## Регрессии 13.1

Проведены 12 целевых проверок фактических функций app.js в Node VM с минимальной моделью DOM. Это не браузерная проверка и не повтор полного прогона Chromium версии 13.0.

## Проверить на реальном iPhone после публикации

- [ ] Сайт показывает v13, не старую версию из кэша.
- [ ] OSRM даёт расстояние для Москвы → Санкт-Петербурга либо показывает корректную резервную подсказку.
- [ ] Переключение FOB, CFR, CIF, FAS не ломает расчёт и меняет назначение затрат.
- [ ] Рекомендация по цели и выбранный базис различимы.
- [ ] Железнодорожный срок при изменении массы сбрасывается для новой массы.
- [ ] Смешанный ценовой рейтинг больше не называется «самым дешёвым».
- [ ] Цена авиационной альтернативы не перекрывает различия остальных вариантов.
- [ ] В Safari текст и селекты не выходят за край, нет случайного масштабирования при фокусе.
- [ ] Если пользователь меняет параметры, карточки и итог пересчитываются без зависания.
- [ ] Проверка пустых полей, отрицательного веса, неподдерживаемого маршрута и недоступного внешнего сервиса — вручную.

## Нерешённые ограничения

Портовая обработка для FAS/FOB разделена по учебной доле 65/35, а не по подтверждённому тарифу порта. Ставки по железной дороге, авиации, морю и мультимодальным схемам модельные. Нет специализированного маршрутизатора грузовиков и расписаний перевозчиков. Цель следующего этапа — упростить тексты и интерфейс после приёмки бизнес-логики.
